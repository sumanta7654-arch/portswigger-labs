SQL Injection | Practitioner

Lab Description

This lab contains an SQL injection vulnerability in the product category filter. The results from the query are returned in the application's response, allowing a UNION attack to retrieve data from other tables. To extract information effectively, we need to identify the database type and its version tracking specifications.

Goal: Determine that the database type is Oracle, map out its column architecture, and execute a query that exfiltrates the database version string using the system table.

Mindset & Strategy

Unlike other database engines (such as MySQL or PostgreSQL), Oracle Database enforces a strict syntax requirement: every SELECT statement MUST include a FROM clause pointing to a valid table.

If we try to inject a standard payload like ' UNION SELECT NULL,NULL--, Oracle will throw an error because the table source is missing. To enumerate columns safely on Oracle, we must explicitly query a built-in system table. We can attempt to use Oracle's default dummy table, dual, or target the version tracking architecture directly via the v$version dictionary view.

Step-By-Step-Execution

1. Locate Entry Vector: Go to the application home screen and click on any available category filter. Your browser URL parameter query string will populate with an entry like: /filter?category=Gifts.

2. Understand Oracle Column Mapping: Because Oracle demands a FROM statement, an entry missing a table target will fail. If you try to map column arrays using the built-in single-row placeholder table via ' UNION SELECT NULL,NULL FROM dual--, configuration constraints might drop the session depending on context. Instead, we can pivot directly to the core version tracking environment table: v$version.

3. Enumerate Columns on System Table: Systematically trace the column count by adding NULL instances pointing to the version table view parameter link:
/filter?category=' UNION SELECT NULL,NULL FROM v$version--
Send the query request. The page resolves into a clean HTTP 200 OK statement response, confirming that the backend database operation handles exactly **two columns**.

4. Exfiltrate the Target Version: In Oracle databases, the version text string information is stored within a specific column identifier named banner. Replace one of the validated NULL placeholders with this target column key:
/filter?category=' UNION SELECT NULL,banner FROM v$version--

5. Verify the Solution: Submit the completed request URL block payload. Examine the visible web layout list rows. The engine will render the internal Oracle software build version text content directly onto the application page template layout, solving the lab tracking module.

Technical Explanation

The web portal dynamically interpolates parameters into an unvalidated database instruction layer:

SELECT name, description FROM products WHERE category = '' UNION SELECT NULL, banner FROM v$version--'

Oracle's strict language validation parsing rules state that omitting a FROM destination triggers a fatal syntax exception. While the dual table is a global dummy table used for executing independent constants, targeting the built-in dynamic performance view v$version allows us to achieve two things simultaneously: fulfilling the structural requirements of the FROM keyword and gaining access to the banner column where system release information is exposed.

How To Fix

°      Deploy Parameterized Prepared Queries: Transition application queries to parameterized interfaces. Binding database parameters ensures the runtime handles inputs strictly as literal data objects, preventing string adjustments from breaking out into structural commands.

°      Restrict Data Dictionary Access: Harden database configurations by applying strict access controls to dictionary views. Restrict public read access to system views like v$version or all_tables to stop unauthorized users from mapping system architecture.

°      Implement Strict Input Whitelisting: Validate incoming routing parameters against a strict alphanumeric allow-list on the server, automatically dropping any input containing structural keywords or relational operators like UNION.
