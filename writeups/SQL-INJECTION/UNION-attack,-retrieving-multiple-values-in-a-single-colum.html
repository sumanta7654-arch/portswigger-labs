SQL Injection | Practitioner

Lab Description

This lab contains an SQL injection vulnerability in the product category filter. While the application's underlying query returns multiple columns, only a single column's content is actually rendered and displayed on the web page. This prevents a standard multi-column data extraction.

Goal: Combine multiple sensitive values into a single string using database-specific concatenation operators, bypass the display limitation to extract credentials from the users table, and log in as administrator.

Mindset & Strategy

During a UNION attack, you might discover that a query returns multiple columns (e.g., two columns), but testing with test strings reveals that only one column's data actually gets printed to the UI layout. If we try to fetch username in the hidden column and password in the visible column, we will only see the passwords.

Our strategy is to use String Concatenation. Instead of selecting fields into separate columns, we merge the username and password fields into a single text block, separated by a distinct delimiter character like a colon (:). This allows us to funnel all our targeted data through the single visible UI container.

Step-By-Step-Execution

1. Map the Parameter Entry: Navigate to the web application home page and click on any category filter link. Observe the URL parameter populate: /filter?category=Pets.

2. Determine Display Architecture: Test the column map count and visibility structure. Injecting ' UNION SELECT NULL,'a'-- loads cleanly and renders the character 'a' on screen, proving that the native query handles **two columns**, but **only the second column is visible** in the application interface template.

3. Inject Concatenation Payload: Because we need to extract both credentials using only the second column, construct a query concatenation using the standard SQL pipelining operators (||):
/filter?category=' UNION SELECT NULL,username || ' : ' || password FROM users--

4. Alternative Database Format Check: If the database flavor uses MySQL or a standard function routing matrix instead of pipelines, deploy the alternative functional equivalent structure:
/filter?category=' UNION SELECT NULL,CONCAT(username,' : ', password) FROM users--

5. Harvest the Concatenated Output: Submit the request payload and examine the rendered layout rows. You will see credential lines cleanly printed as username : password strings. Locate the entry for the administrator user and extract the plain-text password value.

6. Log in and Complete: Go to the account authorization menu dashboard via "My account". Enter administrator along with the extracted credential string. Submitting this valid set solves the lab tracking vector.

Technical Explanation

The web service parses incoming parameters directly into an unparameterized backend database engine statement:

SELECT id, description FROM products WHERE category = '' UNION SELECT NULL, username || ' : ' || password FROM users--'

Even though the template code ignores the first retrieved column database value entirely during UI processing loops, our string concatenation manipulation allows us to condense a multi-column target payload signature down into a single returned field layout structure. The pipeline syntax (||) instructs the database processor to join distinct string fields together sequentially before returning the output dataset records to the server core.

How To Fix

°      Use Parameterized Statements: Implement strongly typed prepared query execution drivers to handle query arguments separately from structural commands, neutralizing characters like pipelines and single quotes.

°      Implement Context-Aware Input Validation: Set up robust validation filters or strict character allow-lists on structural query parameters on the routing layer to automatically reject execution vectors containing relational syntax flags.

°      Enforce Least Privilege Controls: Configure granular database permission structures to restrict application service credentials from reading administrative tables like users entirely.
