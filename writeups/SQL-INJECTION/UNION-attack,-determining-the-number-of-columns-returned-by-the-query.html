SQL Injection | Practitioner

Lab Description

This lab contains an SQL injection vulnerability in the product category filter. The results from the query are returned in the application's response, allowing a UNION attack to exfiltrate data. Building on previous techniques to find the column count, the objective here is to identify which column can hold string/text data.

Goal: Determine which column is compatible with string data, then inject a UNION SELECT payload that returns a specific database-provided random string to solve the lab.

Mindset & Strategy

When executing a UNION attack, matching the column count is only the first step. The database will still throw an error if the data types of the injected columns do not match the data types of the original query columns.

Our strategy is to systematically test individual columns by placing a test string (like 'A') into each position one at a time while keeping the other placeholders as NULL. Once a column accepts the string without throwing a 500 Internal Server Error, we have found our target container for data exfiltration.

Step-By-Step-Execution

1. Determine Column Count: Access the lab and click on any category filter. Test the column count using NULL values in the URL. By sending ' UNION SELECT NULL,NULL,NULL-- and receiving a 200 OK response, you confirm that the query handles exactly **three columns**.

2. Test the First Column for Strings: Replace the first NULL placeholder with a text literal character 'A':
/filter?category=' UNION SELECT 'A',NULL,NULL--
Send the request. If the server throws an error, the first column does not support string data types.

3. Test the Second Column for Strings: Shift the text literal to the second position:
/filter?category=' UNION SELECT NULL,'A',NULL--
Send the request. The application renders the page successfully without errors, indicating that the **second column is compatible with text data**.

4. Inject the Required Value: Note the unique tracking string provided at the top of the lab description page. Replace our test character 'A' with this exact target string:
/filter?category=' UNION SELECT NULL,'X0Y1Z2...',NULL--

5. Verify the Exploit: Submit the finalized payload request. The application will append a new row containing your tracking token to the visible page results, confirming successful execution and solving the lab.

Technical Explanation

A UNION operation combines result sets from multiple queries into a single output table. SQL standards dictate that corresponding columns across joined queries must share compatible data types (e.g., trying to fit a string into an integer field will trigger an allocation crash). By systematically replacing neutral NULL values with explicit string structures, we trace the schema layout dynamically. The successful injection demonstrates that the backend column structure maps cleanly onto text fields.

How To Fix

°      Use Parameterized Statements: Implement strongly typed prepared statements to prevent user input from being executed as structural query commands.

°      Input Sanitization and Validation: Implement an explicit allow-list for category variables on the server-side router to drop unexpected punctuation indicators like single quotes (').

°      Disable Detailed Database Errors: Ensure production configurations suppress raw execution errors, preventing attackers from gaining structural clues during exploitation attempts.
