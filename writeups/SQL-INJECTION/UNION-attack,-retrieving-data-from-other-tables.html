SQL Injection | Practitioner

Lab Description

This lab contains an SQL injection vulnerability in the product category filter. The results from the query are returned directly in the application's response, allowing us to execute a UNION attack. We will leverage this behavior to exfiltrate sensitive credentials from a completely different database table.

Goal: Perform an SQL injection UNION attack to retrieve the usernames and passwords from the users table, then log in as the administrator user.

Mindset & Strategy

Once we know an endpoint maps user input directly into an SQL query, we can use the UNION operator to append our own arbitrary query. However, before extracting data from our true target (the users table), we must satisfy the structural rules of the database: matching the exact column count and ensuring data types are string-compatible.

After validating that the backend query returns compatible structures, we will point our appended query to pull credentials. The database will merge the results, displaying sensitive data directly on the web interface.

Step-By-Step-Execution

1. Locate Entry Point: Access the application home page and click on any category filter. The URL will update with the target parameter, for example: /filter?category=Gifts.

2. Determine Column Structure: Clear the original category value in your URL and test for column count using NULL values:
/filter?category=' UNION SELECT NULL,NULL--
The server returns a clean 200 OK response, proving that the native query handles exactly **two columns**.

3. Verify Data Type Compatibility: To confirm that both columns accept text data types, update the query placeholders with string data:
/filter?category=' UNION SELECT 'a','a'--
The page loads without an error, confirming that both column positions are fully capable of printing string values to the page layout.

4. Exfiltrate Target Credentials: Now that the structure is validated, replace the placeholders with your targeted column and table layout names:
/filter?category=' UNION SELECT username,password FROM users--

5. Harvest the Credentials: Submit the finalized payload request. Scroll through the page output; you will see a list of usernames and passwords appended alongside the normal product entries. Locate the entry for the administrator account and copy its corresponding password hash string.

6. Log in and Solve: Click on "My account" in the navigation menu. Input the username administrator and paste the password you recovered. Upon successful login, the application will register the lab as solved.

Technical Explanation

The backend logic constructs an interpolation sequence similar to this:

SELECT name, description FROM products WHERE category = '' UNION SELECT username, password FROM users--'

Because the UNION operator demands an exact matching blueprint across query results, using 'a','a' allowed us to safely verify the column maps before requesting true values. When the database engine processes our final statement, it joins rows from the users table into the output data stream, forcing the application's presentation templates to cleanly print out administrative credentials directly to the browser view.

How To Fix

°      Enforce Parameterization: Stop constructing query strings dynamically via variable interpolation. Use strongly typed prepared statement interfaces to handle arguments cleanly as parameter inputs rather than executable structural blocks.

°      Apply Strict Routing Whitelists: Enforce strict structural pattern checks or explicit allow-lists on incoming URL parameter variables on the application routing tier, dropping requests that carry illegal characters like single quotes.

°      Database Hardening: Configure explicit database permission limitations to isolate access layers, ensuring that web service application sessions only carry read privileges for specific operational tables, not sensitive configuration structures.
